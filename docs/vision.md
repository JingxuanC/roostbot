# 愿景

> 一句话：**Roost Bot 是你的 Bot 团队的家——家在云上，钥匙在你的电脑上。**

## 问题

现在用 Agent 的人有个共同的别扭：

- 会话是碎的。群里定了方案 A，转头在别处改成方案 B，两条信息落在两个会话里，靠人搬上下文。
- 机器是断的。你的工具、文件、模型额度都在这台电脑上，关盖就没了；想让它一直干活，就得把机器开着。
- 记性是短的。换一个会话，上一次的教训就没了；能留下的是聊天记录，不是可复用的判断。

## 我们做什么

一个网页端的 Bot 平台，三个部件：

1. **云机器**：每个用户（或团队）有一台常驻的云上运行时。Bot 团队住在这里，关掉笔记本也在干活。
2. **本地 DSH**：在你自己的电脑上跑一个 DSH，配对一次，云上的 Bot 就能经它使用本机的工具、文件与模型额度。本地是能力，不是备份。
3. **记忆**：由 causal-memory 提供。Bot 记住的是"我们做过什么判断、后来被证实还是推翻"，不是"上次聊了什么"。

模型成本归用户：用户填自己的 token，平台不转售推理。

## 为谁做

- 一个人，但想让"一支团队"替他盯着几件事
- 一个小团队（2–10 人），共享一批 Bot 和一份记忆
- 以后：不可信的外部租户（那时才需要一人一容器的强隔离）

## 不做什么

- 不做另一个「聊聊天的助手」。没有记忆、没有工具、没有交付物的 Bot 不算产品。
- 不转售模型推理。BYO token 是定价与隐私的基础。
- 不重写 DSH 内核。插件、bundle、profile、配对、反代能表达的，都放在 DSH 外面。
- 不把 A 股投研台当成整个产品。量化是可选插件族，装上才有行情与报告。
- 不做实盘下单、买卖建议、目标价。这条沿用 alpha-desk 的合规边界。

## 三个卖点（按重要性）

1. **一直在**：云机器常驻，Bot 团队不用你开着电脑。
2. **记得住**：记忆层是产品的一部分，不是附加的 RAG。
3. **够得着**：本地 DSH 配对后，云上的 Bot 能用到你本机的东西。

## 成功的样子

- 一个用户配好一台云机器、一对本地 DSH，第二天回来时，Bot 已经按约定把该做的事做了，并且能说出"上次那个判断，后来对了还是错了"。
- 一个团队把 Bot、技能和记忆共享起来，但每个人的私聊只有自己看得见。
