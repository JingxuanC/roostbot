# 界面：安静的团队，诚实的系统

> 状态：方案（2026-11-03）。配套：`workspace.md`（多端）、`messaging.md`（投递语义）、`agent-collaboration.md`（状态）、`budget.md`（配额）。

## 1. 三原则

1. **安静优先**：没事不响。通知只在"需要你"时出现（对齐 `budget`/`scheduling` 的“只在阻断时通知”）。
2. **诚实优先**：不假装在工作、不假装成功。沙箱拒绝、预算耗尽、离线、降级，都直接说。
3. **一个模型，多个窗口**：桌面、浏览器、手机是同一个 workspace 的三个窗口，不是三套产品。

## 2. 信息架构

```
Workspace（可切换）
├─ 房间（人 + 多个 Bot 讨论）
├─ Bot（长期身份；点开是详情，不是聊天）
├─ 需要你（审批、提问、失败）
├─ 时间线（这个 workspace 发生过什么）
├─ 用量（token / Run / 存储）
└─ 设置
   ├─ 设备与配对
   ├─ 连接器
   ├─ 策略（沙箱/工具授权）
   └─ 成员与角色
```

**左边栏只有两件东西**：房间列表 + 一个固定的「需要你」入口。Bot 列表默认折叠在房间下面（一个 Bot 的入口是它在房间里的脸）。

### 3.2 房间

```
│ Roost   ▾  │ 量化研究组          ● 选股师 正在工作      │
│            │──────────────────────────────────────────│
│ 需要你 (2) │ 用户  盘前看一下有什么异动                 │
│            │                                          │
│ 房间       │ 选股师  我先拉一遍涨跌幅和成交额异常        │
│  量化研究组│   ├ 工具 get_a_realtime 600519 …          │
│  复盘组    │                                          │
│            │ 风控官  等选股师的候选，先看数据完整性      │
│            │──────────────────────────────────────────│
│ Bot        │ [ 说点什么…                    ⌘↵ 发送 ]  │
│  选股师    │ 投递方式：立即读取 ▾   回复给：我 ▾        │
│  风控官    │                                          │
└────────────┴──────────────────────────────────────────┘
```

要素：

- 顶部**只有**房间名 + 一行"现在谁在工作"
- 消息流里工具调用折叠成一行（可展开），不刷屏
- 输入框下面两个小下拉：**投递方式**（立即读取 / 排队）与**回复给**（我 / 用户）——这是 `messaging.md` 的 `when` 与 `reply_to`，必须在界面上可见，不能只存在于工具参数
- 默认**不显示**每个人的人设、技能、模型——那些在 Bot 详情里

```
│  颜色 ● ● ● ● ●    图标 [ 程序化 · 上传 · 生成 ]│

│                                              │
│ 能力                                         │
│  技能  [batch-screening ×] [stock-snapshot ×]│
│  工具  允许 [mcp__data__* ×] 禁止 [bash ×]   │
│  审批  ☑ 外网请求  ☐ 写工作区外文件          │
│                                              │
│ 记忆                                         │
│  范围 ☑ 团队 ☑ 房间 ☐ 个人   保留 [180 天 ▾] │
│                                              │
│ 模型                                         │
│  档位 [standard ▾]   额度 [跟随工作区]        │
│                                              │
│ 定时                                         │
│  [+ 添加 routine]   每日 15:30 · 盘后复核     │
└──────────────────────────────────────────────┘
```

规则：

1. **能力区只能由 admin 改**（`sandboxing.md` / `bot-manifest`）；成员改身份与人设
2. 人设编辑**带版本与留痕**：保存后产生事件，可回滚（对齐 SOUL.md 的单源 + drift 思路）
3. 暂停 = 不接新请求，进行中的回合跑完（不是 kill）
4. 删除 = 软删 7 天（期间可恢复），之后才清会话与记忆

```
│ ⬆ 纸面交易      0.2.0 → 0.3.0   [升级]        │
│    ⚠ 需要 DSH ≥ 0.2.1，当前 0.2.1 兼容        │
│ ─────────────────────────────────────────    │
│ 市场                                          │

│  新闻雷达   0.1.0   [安装]                    │
│  因果记忆   0.4.2   [安装]                    │
└──────────────────────────────────────────────┘
```

三个必须显示的东西：

1. **兼容性**：插件要求的 DSH 版本区间 vs 当前版本（不兼容时**禁止安装**，不是装完再炸）
2. **它要什么**：面板/工具/技能/数据集/磁盘大小——用户要知道代价
3. **谁装的、什么时候**（审计）

安装流程（admin）：

```
选择插件 → 预检（版本/依赖/磁盘/权限）→ 确认（显示它将获得的能力）
   → 控制面生成 lockfile → runtime sync → 重启声明 → 成功/回滚
```

**失败要能回滚**：安装前给 profile 打快照，失败自动恢复（`workspace.md` 的快照能力）。

### 3.9 对话里的产物渲染

消息可能带一张图、一份 PDF、一个 HTML 报告、一张表。规则（完整见 `artifacts.md`）：

| 产物 | 聊天里 | 打开方式 |
|---|---|---|
| 图片 | 缩略图（长边 320），点击灯箱 | 原图 / 保存 |
| PDF | 卡片：文件名 + 大小 + 首页缩略图 | 下载 / 新标签（沙箱） |
| HTML 报告 | 卡片：标题 + 摘要 + 「打开」 | **只在沙箱 iframe 里**，绝不注入聊天 DOM |
| 表格 | 前 20 行 + 行数 | 下载 / 展开 |
| 代码 | 代码块，> 20 行折叠 | 复制 |

**三条渲染纪律**：

1. **不内嵌 HTML**：产物是脚本，只能进独立源的 iframe（或新标签）
2. **流式渲染幂等**：Markdown 按块提交，未闭合不乱跳；同一段重放不重复
3. **占位不跳版**：图片/PDF 加载前先占好高度，避免滚动位置被顶掉

**流式与工具**：

```
选股师  我先拉一遍涨跌幅 ▍            ← 光标在流式末尾，旁边有「停止」
  ├ 工具 get_a_realtime · 1.2s        ← 折叠一行，可展开看参数/结果
```

工具结果超过阈值只显示头部 + 路径，全文在产物里（可点开）。

图标规则（程序化默认、状态环、群聊拼合）见 [`bot-identity.md`](bot-identity.md)。

两个开关的分工：

## 4. 多端差异

| 端 | 差异 |
|---|---|
| 桌面 | 双栏（列表 + 内容）；⌘K 命令板；本地能力节点状态在设置里 |
| 浏览器 | 同桌面，但无本地节点；宽度 <1024 收成单栏 |
| 手机 | 单栏 + 底部 Tab（房间 / 需要你 / 设置）；审批用全屏 sheet；不支持双栏 |

**深链**：`/w/<id>/room/<id>`、`/w/<id>/bot/<id>`、`/w/<id>/needs`——通知点击要能精确落到对象（这是 `notification` 的硬要求）。

## 5. 状态必须可见（诚实原则的落地）

| 状态 | 界面表现 |
|---|---|
| 流式生成中 | 消息末尾光标 + 停止按钮；**不显示假进度条** |
| 工具运行中 | 折叠行显示工具名与耗时；超过 10s 显示"仍在运行" |
| 沙箱拒绝 | 该行红色标注 + "为什么"，并给"允许一次"的入口（要人批） |
| 预算耗尽 | 顶部横幅 + 输入框禁用并说明"本周期额度已用完，X 重置" |
| 离线 | 顶部细条"离线，读到的是缓存"；发送按钮禁用 |
| 降级 | 模型代理不可用 → "模型暂不可用，已排队，恢复后自动继续" |
| 重启恢复 | 消息里出现"宿主重启了，这一轮从断点继续"（来自 `messaging` 的 resume 框） |

## 8. 交互细则

- **一次一个说话者**：房间里多个 Bot 同时"正在输入"时，只有当前 speaker 有动画，其余显示"等待中"
- **停止**：任何流式回答都能停，停止后保留已生成内容（标"已停止"）
- **重发**：消息带 `idem`，重发不产生重复；界面显示"已重发（去重）"
- **批准**：单次批准后卡片消失并留一行历史"已允许（一次）"
- **键盘**：⌘K 命令板、⌘↵ 发送、Esc 关闭面板、j/k 在时间线移动
- **滚动**：新消息到达时不强制跳底（除非已在底部）

## 9. 性能预算

| 项 | 目标 |
|---|---|
| 首屏可交互 | < 1.5s（局域网） |
| 消息流增量渲染 | 首字节 < 100ms |
| 时间线 1000 条滚动 | 60fps（虚拟列表） |
| 打包体积 | 首屏 JS < 250KB gzip |

## 10. 不做

1. 不做默认仪表盘（用户打开是为了对话，不是为了看图表）
2. 不做假进度、假在线人数、假指标
3. 不做无限 feed（时间线有明确时间范围与筛选）
4. 不做"AI 味"的渐变卡片与发光边框（对齐 `ui-design` 的审美约束）
5. 不在界面里出现 token 明文、密钥、内部 id（id 只在开发模式显示）
