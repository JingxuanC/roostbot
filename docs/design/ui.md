# 界面：安静的团队，诚实的系统

> 状态：方案（2026-11-03）。配套：`workspace.md`（多端）、`messaging.md`（投递语义）、`agent-collaboration.md`（状态）、`budget.md`（配额）。

## 1. 三原则

1. **安静优先**：没事不响。通知只在"需要你"时出现（对齐 `budget`/`scheduling` 的“只在阻断时通知”）。
2. **诚实优先**：不假装在工作、不假装成功。沙箱拒绝、预算耗尽、离线、降级，都直接说。
3. **一个模型，多个窗口**：桌面、浏览器、手机是同一个 workspace 的三个窗口，不是三套产品。

## 2. 信息架构

```
Workspace（可切换）
├─ 房间（人 + 多个 Bot 讨论）
├─ Bot（长期身份；点开是详情，不是聊天）
├─ 需要你（审批、提问、失败）
├─ 时间线（这个 workspace 发生过什么）
├─ 用量（token / Run / 存储）
└─ 设置
   ├─ 设备与配对
   ├─ 连接器
   ├─ 策略（沙箱/工具授权）
   └─ 成员与角色
```

**左边栏只有两件东西**：房间列表 + 一个固定的「需要你」入口。Bot 列表默认折叠在房间下面（一个 Bot 的入口是它在房间里的脸）。

## 3. 关键界面（线框）

### 3.1 配对

```
┌──────────────────────────────────────┐
│              Roost                   │
│                                      │
│   输入另一台设备上显示的配对码         │
│   ┌──────────────────────────┐       │
│   │   4 2 8 1 9 3            │       │
│   └──────────────────────────┘       │
│   [ 配对 ]                            │
│                                      │
│   没有配对码？先登录账号 →            │
└──────────────────────────────────────┘
```

规则：6 位数字、自动聚焦、粘贴自动分段、错误就地显示（不弹窗）、成功后直接进上次的 workspace。

### 3.2 房间

```
┌────────────┬──────────────────────────────────────────┐
│ Roost   ▾  │ 量化研究组          ● 选股师 正在工作      │
│            │──────────────────────────────────────────│
│ 需要你 (2) │ 用户  盘前看一下有什么异动                 │
│            │                                          │
│ 房间       │ 选股师  我先拉一遍涨跌幅和成交额异常        │
│  量化研究组│   ├ 工具 get_a_realtime 600519 …          │
│  复盘组    │                                          │
│            │ 风控官  等选股师的候选，先看数据完整性      │
│            │──────────────────────────────────────────│
│ Bot        │ [ 说点什么…                    ⌘↵ 发送 ]  │
│  选股师    │ 投递方式：立即读取 ▾   回复给：我 ▾        │
│  风控官    │                                          │
└────────────┴──────────────────────────────────────────┘
```

要素：

- 顶部**只有**房间名 + 一行"现在谁在工作"
- 消息流里工具调用折叠成一行（可展开），不刷屏
- 输入框下面两个小下拉：**投递方式**（立即读取 / 排队）与**回复给**（我 / 用户）——这是 `messaging.md` 的 `when` 与 `reply_to`，必须在界面上可见，不能只存在于工具参数
- 默认**不显示**每个人的人设、技能、模型——那些在 Bot 详情里

### 3.3 需要你（审批与提问）

```
┌──────────────────────────────────────────┐
│ 需要你 · 2                               │
│──────────────────────────────────────────│
│ ⚠ 选股师 请求发送邮件                     │
│   to: research@example.com               │
│   subject: 今日异动摘要                   │
│   [ 拒绝 ]            [ 允许这一次 ]      │
│                                          │
│ ? 风控官 在等一个回答                     │
│   口径用 TTM 还是最近一期？               │
│   [ TTM ]  [ 最近一期 ]  [ 自己输入 ]     │
└──────────────────────────────────────────┘
```

规则：卡片必须显示 **谁、要做什么、影响什么**；批准是单次，长期授权要去设置里显式打开（防误点）。

## 4. 多端差异

| 端 | 差异 |
|---|---|
| 桌面 | 双栏（列表 + 内容）；⌘K 命令板；本地能力节点状态在设置里 |
| 浏览器 | 同桌面，但无本地节点；宽度 <1024 收成单栏 |
| 手机 | 单栏 + 底部 Tab（房间 / 需要你 / 设置）；审批用全屏 sheet；不支持双栏 |

**深链**：`/w/<id>/room/<id>`、`/w/<id>/bot/<id>`、`/w/<id>/needs`——通知点击要能精确落到对象（这是 `notification` 的硬要求）。

## 5. 状态必须可见（诚实原则的落地）

| 状态 | 界面表现 |
|---|---|
| 流式生成中 | 消息末尾光标 + 停止按钮；**不显示假进度条** |
| 工具运行中 | 折叠行显示工具名与耗时；超过 10s 显示"仍在运行" |
| 沙箱拒绝 | 该行红色标注 + "为什么"，并给"允许一次"的入口（要人批） |
| 预算耗尽 | 顶部横幅 + 输入框禁用并说明"本周期额度已用完，X 重置" |
| 离线 | 顶部细条"离线，读到的是缓存"；发送按钮禁用 |
| 降级 | 模型代理不可用 → "模型暂不可用，已排队，恢复后自动继续" |
| 重启恢复 | 消息里出现"宿主重启了，这一轮从断点继续"（来自 `messaging` 的 resume 框） |

## 6. 设计系统

**色彩**（冷底 + 暖强调，鸟巢的暖）

| token | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `bg` | `#0B0C0E` | `#FAFAF8` | 页面底 |
| `surface` | `#141619` | `#FFFFFF` | 卡片 |
| `border` | `#24272C` | `#E6E3DC` | 分隔 |
| `ink` | `#E8EAEF` | `#1B1D21` | 主文字 |
| `muted` | `#8B93A3` | `#6B7280` | 次要 |
| `accent` | `#D8AB52` | `#B8862F` | 主强调（按钮、焦点） |
| `ok` | `#7FB37F` | `#3F7A44` | 成功 |
| `warn` | `#D9A441` | `#9A6B12` | 警告 |
| `danger` | `#D2726A` | `#A63A32` | 危险 |

**字体**：`-apple-system, "SF Pro Text", "PingFang SC", …`；等宽用于 id/代码。
**字号**：12 / 13 / 14 / 16 / 20 / 24 / 32；行高 1.5（正文）、1.3（标题）。
**间距**：4 的倍数（4/8/12/16/24/32/48）。
**圆角**：6 / 10 / 14 / 999。
**动效**：120 / 180 / 240ms，`cubic-bezier(.2,.8,.2,1)`；遵守 `prefers-reduced-motion`。

## 8. 交互细则

- **一次一个说话者**：房间里多个 Bot 同时"正在输入"时，只有当前 speaker 有动画，其余显示"等待中"
- **停止**：任何流式回答都能停，停止后保留已生成内容（标"已停止"）
- **重发**：消息带 `idem`，重发不产生重复；界面显示"已重发（去重）"
- **批准**：单次批准后卡片消失并留一行历史"已允许（一次）"
- **键盘**：⌘K 命令板、⌘↵ 发送、Esc 关闭面板、j/k 在时间线移动
- **滚动**：新消息到达时不强制跳底（除非已在底部）

## 9. 性能预算

| 项 | 目标 |
|---|---|
| 首屏可交互 | < 1.5s（局域网） |
| 消息流增量渲染 | 首字节 < 100ms |
| 时间线 1000 条滚动 | 60fps（虚拟列表） |
| 打包体积 | 首屏 JS < 250KB gzip |

## 10. 不做

1. 不做默认仪表盘（用户打开是为了对话，不是为了看图表）
2. 不做假进度、假在线人数、假指标
3. 不做无限 feed（时间线有明确时间范围与筛选）
4. 不做"AI 味"的渐变卡片与发光边框（对齐 `ui-design` 的审美约束）
5. 不在界面里出现 token 明文、密钥、内部 id（id 只在开发模式显示）

## 11. 分期

### v0
- 配对页、房间（单房间）、消息流、输入框（投递方式可见）
- **验收**：配对 → 进房间 → 发一句 → 看到流式回答；断网时出现离线条

### v1
- 需要你（审批 + 提问）、Bot 详情、用量、连接器卡片
- **验收**：发邮件需批准；额度 80% 出现提醒；审批后卡片留历史

### v2
- 时间线、多端深链、键盘全栈、移动端 sheet
- **验收**：手机上点通知落到具体房间的那条消息

## 12. 待决问题

1. **Bot 列表放左栏还是房间内的面孔？** 倾向：房间内面孔 + 左栏折叠列表。
2. **投递方式（立即/排队）默认哪个？** 倾向：默认"立即读取"，高级用户可改默认。
3. **审批是否支持"本会话允许"**？（`messaging`/`sandbox` 都提到单次授权）倾向：v1 只做单次，长期授权放设置。
4. **移动端是否支持发图/语音**？倾向：v1 支持发图，语音后置。
