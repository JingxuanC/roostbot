# 前端 UI 重设计：把 Roost 做得安静、简洁、优雅

> 状态：**已实现（2026-11-05）**：浅蓝白主题、无侧栏房间壳、抽屉设置入口、移动端适配。
> 实现见 `apps/web/styles-blue.css` + `apps/web/index.html` + `apps/web/app.js`；本文保留设计依据与验收标准。
> 上游：`ui.md`（三原则与信息架构）、`bot-avatar.md`（鸟）。本文只回答一件事：
> 现有实现如何收敛成「简洁优雅」，以及每一步怎么验收。

## 0. 先说结论

简洁优雅不是再换一套颜色，而是**删掉三类噪声**：

1. **入口竞争**：同一个动作在顶部、侧栏、房间里各有一个入口。
2. **卡片依赖**：用边框、圆角、阴影、pill 来分区，而不是用留白和排版。
3. **状态外露**：把内部状态（轮次、审批、暂停、用量）同时用文字、颜色、徽章、动画表达。

方向建议：**浅蓝纸感（默认）+ 墨色文字 + 单一深蓝强调**；白色只留给 surface（顶栏、输入框、
设置内容区），让「浅蓝 / 白」形成层次。深色作为后续可选项，不是二选一。官网随后同步同一套蓝白。

鸟是页面上唯一允许高饱和的元素，其余全部退到灰阶。

产品形态再补一条硬约束（2026-11-05 确认）：

> **打开就简洁：默认界面只有房间（对话）；其他所有东西都是设置页。**

也就是说：没有常驻侧栏、没有顶部功能导航、没有仪表盘。房间就是产品本身；
Bot 管理、房间管理、插件、用量、定时、连接器、设备、审计全部住在 `/settings/*` 里。

## 1. 现状诊断（基于当前实现与截图）

| 现象 | 具体表现 | 为什么伤害「优雅」 |
|---|---|---|
| 顶部导航过载 | 顶部同时有 Bot、需要你、新建房间、插件、已安装、插件面板、用量、定时任务、连接器、设置、登录、配对 | 用户不知道主任务是什么；像后台管理台 |
| 重复入口 | 顶部「Bot/需要你/设置」与侧栏「Bot/需要你/设置」重复 | 注意力被切成两半 |
| 卡片化过度 | Bot 列表是卡片、设置分区是卡片、消息也是气泡卡片 | 页面像一堆盒子，缺少呼吸 |
| 状态标签泛滥 | 「在岗」「暂停」「正在工作」「本轮进行中」「排队中」同时出现 | 状态应该安静，只在需要时出现 |
| 深色 + 琥珀 | 深底 + 高饱和琥珀 + 发光/描边 | 更像监控大屏，不像长期工作的工具 |
| 字号偏小且密 | 13px 为主、行高紧、灰色元信息多行 | 长对话阅读累；优雅感首先来自可读性 |
| 彩色元素竞争 | 鸟的彩色 + 琥珀按钮 + 绿色徽章 + 蓝色链接 | 鸟不再是主角 |
| 输入区重 | 大圆角输入框 + 高亮描边 + 右侧大按钮 | 房间里最重的元素应该是消息，不是输入框 |

结论：**不是缺少设计，而是入口与装饰太多。优雅靠减法。**

## 2. 四条设计原则

1. **一屏一个主任务**：房间的主任务是读与说；Bot 页的主任务是看身份与设置；
   每个页面只保留一个主按钮，其余收进「更多」或设置。
2. **排版分区，不用边框分区**：优先用 24/32/48 的留白、字号与字重分隔；
   一屏最多一层卡片（弹层/抽屉），列表与设置区不用卡片包卡片。
3. **颜色只做三件事**：强调主操作、标出「需要你」、区分人和 Bot。
   鸟的羽毛颜色是唯一允许的「多彩」；UI 本身只使用浅蓝、白、墨色、灰阶。
4. **状态安静且可查**：默认只显示「需不需要你」；轮次、工具、用量在需要时展开，
   不长期占据视觉中心。

## 3. 视觉系统（目标 token）

### 3.1 颜色

| token | 值 | 用途 |
|---|---|---|
| `--canvas` | `#F2F8FC` | 页面底色（浅蓝白） |
| `--surface` | `#FFFFFF` | 顶栏、输入框、抽屉、设置内容区（白） |
| `--sunken` | `#EAF2F8` | 选中行、代码块、次级区域 |
| `--ink` | `#15232E` | 主文字（蓝黑） |
| `--ink-2` | `#3B4E5D` | 次级文字 |
| `--muted` | `#5F7485` | 说明文字（对底色 ≥4.5:1） |
| `--line` | `#D9E6F0` | 唯一的分隔线颜色 |
| `--accent` | `#1F5C86` | 文字/图标强调、主按钮（对白底 ≥4.5:1） |
| `--accent-fill` | `#2F7CAF` | 选中线、焦点、发送按钮；浅色用户气泡用 `#E1EFF9` |
| `--danger` | `#B24A45` | 破坏性操作 |
| `--ok` | `#4E7D6A` | 成功/在线，极小面积 |

规则：
- 主按钮用深蓝 `--accent` + 白字；选中态/焦点用 `--accent-fill`；次按钮是透明底 + `--line` 边框。
- 不再使用发光、渐变、玻璃拟态；阴影只给浮层（`0 12px 32px -24px rgba(30,60,90,.28)`）。
- 深色主题后续再做：同一套语义 token，先保证浅色优雅。

### 3.2 字体与尺度

系统字体栈（零依赖）；中文优先 PingFang/思源，数字用等宽可选。

| 级别 | 字号 / 行高 | 用途 |
|---|---|---|
| Display | 40 / 1.15 | 配对页、空态大标题（少用） |
| Page | 26 / 1.25 | 页面标题（Bot、设置、市场） |
| Section | 18 / 1.4 | 设置分组、卡片标题 |
| Body | 14 / 1.7 | 正文、消息 |
| Small | 13 / 1.6 | 元信息（角色、时间） |
| Caption | 12 / 1.5 | 表格头、辅助说明（最浅） |

- 标题 `letter-spacing: -0.02em`，正文 0；中文行高不小于 1.65。
- 一屏最多 3 个字号层级（标题/正文/说明），避免「大小灰字都不同」。

### 3.3 形状与间距

- 圆角：控件 10、卡片/面板 14、弹层 16；头像保持圆形或 8px，不随卡片变。
- 间距阶梯：4 / 8 / 12 / 16 / 24 / 32 / 48；页面左右 24（桌面 32），内容最大宽 760（聊天）/ 880（列表）。
- 分隔：1px `--line`，优先使用「一条线 + 留白」，不用整块边框。
- 图标：1.5px 线性、18px，统一从同一套几何；不用 emoji 当图标。

## 4. 布局与页面

### 4.1 应用外壳：没有外壳

默认打开**直接进入最后一个房间**：整页只有顶栏（房间名 + 鸟群 + 一行工作状态）、消息流、输入框。
没有常驻侧栏，也没有顶部功能导航。

```
┌────────────────────────────────────────────────────────────┐
│ ≡   [鸟群] 量化研究组        · 选股师正在工作            ⋯  │  ← 唯一一条顶栏
│────────────────────────────────────────────────────────────│
│                                                            │
│                          盘前看一下有什么异动  ← 用户气泡   │
│                                                            │
│ 选股师  研究                                               │
│ 先拉一遍涨跌幅和成交额异常……                               │
│ ▸ 调用 get_a_realtime · 1.2s                               │
│                                                            │
│ 风控官  风控                                               │
│ 等候选，先看数据完整性。                                    │
│                                                            │
│────────────────────────────────────────────────────────────│
│ [ 说点什么…                                    ⌘↵  ↑ ]     │
│ 投递：立即读取 · @ 提醒成员（聚焦时才出现）                 │
└────────────────────────────────────────────────────────────┘
```

- `≡`（左上）打开抽屉：房间列表、新建房间、设置；这是唯一的全局导航入口。
- `⋯`（右上）只放当前房间的动作：房间设置、成员、审批、离开；不放全站功能。
- 顶栏状态只有一行；「需要你」用 `≡` 上的一个小圆点提示，不单独占一列。
- 没有房间时：整页只有一句「还没有房间」+ 一个主按钮；不用卡片/插画堆满。
- 移动端同一结构：顶栏更矮，抽屉从左侧滑出。

**路由**

| 路由 | 内容 |
|---|---|
| `/` | 最后一个房间（无房间 → 空态） |
| `/rooms/:id` | 房间；`?` 抽屉可切换 |
| `/settings` | 设置外壳（左栏只在设置内出现） |
| `/settings/appearance` | 外观/密度/动效/强调色 |
| `/settings/notifications` | 通知（安静优先） |
| `/settings/devices` | 设备与配对 |
| `/settings/bots` | Bot 列表与管理 |
| `/settings/rooms` | 房间管理 |
| `/settings/plugins` | 插件与面板 |
| `/settings/schedules` | 定时任务 |
| `/settings/connectors` | 连接器 |
| `/settings/usage` | 用量与预算 |
| `/settings/audit` | 审计日志 |

设置页可以有自己的左栏（因为用户已经明确进入"设置"这个上下文），但左栏只属于 `/settings/*`，
不能出现在房间界面。

### 4.1.1 移动端 Web：不是缩小版，是同等优先级

![移动端三屏：房间 / 抽屉 / 设置](docs/assets/ui-refresh-mobile.png)

**目标环境**：360–430 CSS px 宽；iOS Safari 16+、Android Chrome 110+；横屏可用。
不要求原生 App，手机浏览器打开就是完整体验。

**基础约束**

- `viewport` 允许缩放（不写 `maximum-scale=1`）；不锁定方向。
- 顶栏避开刘海：`padding-top: env(safe-area-inset-top)`；底部输入框避开 Home 指示条：
  `padding-bottom: calc(12px + env(safe-area-inset-bottom))`。
- 全部触控目标 **≥44×44**：`≡`、`⋯`、发送、列表行、抽屉项。只有
  `@media (hover:hover)` 才启用 hover；触屏用 `:active` 反馈。
- 输入控件字号 **≥16px**（防 iOS 聚焦自动放大）；配对码 `inputmode="numeric"` +
  `autocomplete="one-time-code"`；消息输入 `enterkeyhint="send"`。
- 高度用 `100dvh` / `svh`，不用 `100vh`；键盘弹出用 `visualViewport` 校正 composer，
  聚焦时把输入框滚到可见区域。
- 消息区 `overscroll-behavior-y: contain`，避免下拉刷新误触；不拦截浏览器返回手势。
- 无侧栏：`≡` 打开抽屉（宽 `min(320px, 86vw)`，焦点陷阱 + Esc + scrim 关闭）；
  设置是**全屏列表 → 详情**，不出现桌面左栏。
- 性能：首屏目标 <200KB gzip（不含用户图片），无外部字体/CDN；移动端不用
  `backdrop-filter`（顶栏改用实色白）；动画只做状态变化，`prefers-reduced-motion` 下关闭。
- 无障碍：支持 200% 文字缩放；长按可选中文字；关键操作不依赖 hover；对比度 ≥4.5:1。

**测试矩阵**

| 场景 | 尺寸 |
|---|---|
| iPhone SE | 375 × 667 |
| iPhone 14/15 | 390 × 844 |
| Pixel | 412 × 915 |
| 横屏 | 844 × 390 |
| 大字号 / 200% 缩放 | 390 × 844 |

每个 P0/P1 阶段都要附 390×844 与 375×667 的截图；不允许横向滚动（`scrollWidth === innerWidth`）。

### 4.2 房间（主界面）

```
┌────────────────────────────────────────────────────────────┐
│ ← 量化研究组   [鸟群图标]                  · 选股师正在工作 │
│────────────────────────────────────────────────────────────│
│                                                            │
│                                    盘前看一下有什么异动  ← 用户气泡（右，浅蓝）│
│                                                            │
│ 选股师  研究                                               │
│ 我先拉一遍涨跌幅和成交额异常。                              │  ← Bot 消息：无气泡，直接排版│
│ ▸ 调用 get_a_realtime · 1.2s                               │  ← 工具一行，可展开│
│                                                            │
│ 风控官  风控                                               │
│ 等选股师的候选，先看数据完整性。                            │
│                                                            │
│────────────────────────────────────────────────────────────│
│ [ 说点什么…                                    ⌘↵ 发送 ]   │
│ 投递：立即读取   ·   @ 提醒成员                             │  ← 次级操作只在聚焦时出现│
└────────────────────────────────────────────────────────────┘
```

- 消息区是唯一主角：Bot 消息不用气泡，用「头像 + 名字 + 角色 + 正文」形成节奏；
  用户消息才用右对齐浅色气泡，人和 Bot 一眼可分。
- 轮次状态从顶部 pill 行改为**头部一行小字 + 消息流里的状态行**；只有当前发言者有细小的
  working 环，不再同时出现「本轮进行中/排队中」多个 pill。
- 工具调用默认一行（图标 + 名称 + 耗时），可展开；长结果收进产物。
- 输入框：一个 12px 圆角容器，聚焦时只有 2px accent ring；发送是 icon 按钮，不是大色块。
- 空态：一句「说点什么，开始一轮」+ 一只小鸟，不用大卡片。

### 4.3 Bot 列表

- 从卡片改为**行**：40px 鸟 + 名字（15/600）+ 角色（13 muted）+ 最右侧状态点（仅 paused 显示文字）。
- 行高 56，分隔用 1px 线或留白；hover 只变 `--sunken`，不做位移/阴影。
- 末尾一个幽灵按钮「新建 Bot」，不放整块卡片。
- 元信息（model、approval、tools）移进详情页，不在列表出现。

### 4.4 Bot 详情 / 设置（位于 `/settings/bots`）

- 顶部：40px 鸟 + 名称 + 角色 + 一个主按钮（暂停/启用）；删除收进「更多」。
- 分组用标题 + 细线，不用卡片：身份 / 人设 / 能力 / 记忆 / 模型 / 危险区。
- 表单两列（label 左 120px，控件右），桌面一屏可读完；移动端单列。
- 保存栏固定在底部，只在有改动时出现（「已保存 / 保存」）；不长期占位。

### 4.5 其他页面（全部位于 `/settings/*`）

- 插件/用量/定时任务/连接器：统一 **页面标题 + 一行说明 + 表格/列表**，
  表格用行与线，不用卡片；状态用文字（必要时一个点），不用彩色 pill。
- 审批：侧滑抽屉（右 420px）而不是弹窗套弹窗；一条审批单只出现一个主按钮「允许这一次」，
  拒绝是次按钮，长期授权在设置里显式打开。
- 配对页保持现有居中卡片，但去掉装饰描边，只留输入与主按钮。

## 5. 动效与可达性

- 动效只用于**状态变化**：180ms `ease-out` 的背景/透明度；页面切换不做入场动画。
- 唯一的循环动画：Bot「正在工作」的鸟环，1.5px 细线，2.4s；`prefers-reduced-motion` 下停止。
- 焦点：2px accent outline + 2px offset，所有可交互元素可见。
- 正文对比 ≥4.5:1；说明文字 ≥4.5:1；不用颜色作为唯一状态线索。
- 消息流 `aria-live="polite"` 只播报轮次开始/结束，不逐条播报。
- 键盘：`⌘K` 命令面板、`⌘↵` 发送、`Esc` 关闭抽屉、Tab 顺序与视觉顺序一致。

## 6. 落地顺序（每步都可单独验收）

| 阶段 | 范围 | 不改行为 | 验收 |
|---|---|---|---|
| P0 | 设计 token + 默认房间壳（顶栏/抽屉/设置路由） | 是 | 截图对比；全量测试；对比度检查；390/375 无横向滚动 |
| P1 | 房间：消息、工具行、输入框、轮次状态（去掉常驻侧栏） | 是 | 两条真实回复截图；键盘路径；iOS 键盘不遮输入框 |
| P2 | 设置页外壳 + Bot 列表/详情/设置表单 | 是 | 桌面/移动截图；表单可用 |
| P3 | 市场/已安装/插件面板/用量/定时/连接器/审批统一 | 是 | 每页截图 + 空态/错误态 |
| P4 | 移动端、动效、a11y、深色（可选） | 否（只视觉） | axe/对比度、键盘、reduced-motion |

原则：P0–P3 只改 CSS/DOM 结构与文案，**不改 API、事件、状态机**；每一步保持 1,249 测试全绿，
并保存 before/after 截图到 `docs/assets/ui-refresh/`。

## 8. 实现记录（2026-11-05）

已落地：

- **浅蓝白主题**：`apps/web/styles-blue.css` 覆盖 `styles.css` 的 token 与外壳样式，`<meta color-scheme="light">`；白 surface 只用于顶栏/输入框/设置内容。
- **打开就是房间**：房间视图去掉常驻侧栏；`≡` 打开抽屉（房间 + 需要你 + 管理入口），`⋯`/房间设置保留房间动作；顶栏只留标题、鸟群和安静的工作状态。
- **其他都是设置页**：抽屉「管理」列出 Bot / 插件 / 用量 / 定时 / 连接器 / 审批 / 设置；管理页统一 `← 房间` 返回、隐藏旧顶部导航。
- **移动端**：抽屉 `min(320px, 86vw)`、44px 触控、16px 输入、`env(safe-area-inset-bottom)`、375/390 无横向滚动。
- **设备会话**：配对 token 持久化到 localStorage（`lib/session-store.js`），刷新/重开手机网页直接回到上次房间；401 时清除。账号会话仍用 HttpOnly cookie。
- **回归测试**：新增 `session-store.test.ts` 与 `shell-theme.test.ts`；全量测试保持通过。

### 与设计稿的偏差

- 管理页仍使用既有 hash 路由（`#/bots`、`#/plugins`、`#/usage`…），没有迁移到 `/settings/*` 前缀；入口已统一收进抽屉。路由迁移留作后续。
- 消息区保留了「加载更早的消息」按钮；短会话时会出现在消息上方。
- `发送` 仍是文字按钮而不是纯图标，保证可读性。
