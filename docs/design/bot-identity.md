# Bot 图标：默认就体面，可选才生成

> 状态：方案（2026-11-03）。配套：`ui.md`（界面）、`storage.md`（图片存储）、`artifacts.md`（产物）。

## 1. 一句话

**每个 Bot 一出生就有一个程序化生成的图标（确定性、零成本、不需要任何 API key）；上传或 AI 生成是升级项，不是前提。**

理由：BYO token 的用户未必有图片生成额度，而"新 Bot 是一个灰方块"是最伤体验的默认。OpenMausBot 的 mascot/裁剪/生成三件套很成熟，但它把"生成"当主路径；我们把**程序化图标**当主路径、生成当可选。

## 2. 三层身份

| 层 | 是什么 | 谁决定 |
|---|---|---|
| **形（glyph）** | 由 bot id 哈希出的几何徽记（6 个族） | 程序，确定性 |
| **色（palette）** | 8 个强调色之一 + 中性底 | 程序默认，人可改 |
| **图（image）** | 上传或生成的位图（可选） | 人 |

三层可以单独改：改色不动形，换图仍有形可回落。

## 3. 程序化图标（默认）

```
输入：bot id（稳定，不改）
hash = fnv1a(id)
family  = hash % 6        → 蛋 / 羽 / 翼 / 眼 / 巢 / 喙
palette = hash / 6 % 8     → 8 个强调色之一
rotate  = hash / 48 % 4    → 0/90/180/270（同族不同姿态）
dots    = hash / 192 % 4   → 0..3 个装饰点（同族进一步区分）
```

- 输出 **SVG**（矢量，任意尺寸不糊，体积 < 2KB）
- 96×96 圆角方形底（`radius = 24`），中性底 + 强调色描线 + 一处填充
- 深浅色各一套配色（浅色底上用深一档的强调色）
- **确定性**：同一 id 永远同一图标；不同 id 高概率不同（6×8×4×4 = 768 组合）

**为什么不用首字母**：中文名首字重复率极高（"数据官/事件官/复盘官"），而且首字母块看起来像 placeholder。几何徽记更像"团队里有个人"。

## 4. 尺寸与变体

| 场景 | 尺寸 | 备注 |
|---|---|---|
| 消息行、成员列表 | 24 / 32 | SVG 直接内联 |
| 侧栏、房间成员 | 40 | |
| Bot 详情头部 | 56 | |
| 设置预览 | 96 | |
| 源图 | **256**（位图）或 SVG | 只存一份，前端降采样 |

位图存储：`256×256` WebP（质量 82），单张目标 < 40KB。上传原图保留 7 天（可重裁），之后只留 256。

## 5. 上传与生成（可选）

### 上传

```
选择文件 → 校验（MIME 四栅格、≤10MB、SVG 拒收）→ 剥 EXIF
  → 居中裁 1:1 → 转 256 WebP → ContentStore.put → 绑定 bot
```

### AI 生成

只在该 workspace **有图片 provider key** 时出现（OpenAI / xAI / 自定义 OpenAI 兼容）：

```
方向输入（可选，≤200 字）+ 固定风格前缀
  → 生成 1024×1024 → 转 256 WebP → 预览 → 用户确认才保存
```

- 生成是**显式动作**，显示"将消耗一次图片生成额度"
- 有并发保护：生成前快照当前状态，回来发现已被改则 **409**（不覆盖别人的新编辑）
- 生成失败**不改变**现有图标

## 6. 裁剪模型（不服务端裁图）

存两个数：`zoom`（1–3）与 `focus`（x,y ∈ 0..1），渲染时用 CSS：

```css
object-fit: cover;
object-position: calc(focus.x * 100%) calc(focus.y * 100%);
transform: scale(zoom);
```

好处：随时可重裁、不重复存图、前端零成本；坏处：极端 zoom 会糊——所以上限 3、源图 ≥ 256。

## 7. 状态

| 状态 | 表现 | 为什么 |
|---|---|---|
| 空闲 | 正常 | — |
| **工作中** | 外圈一道**缓慢**呼吸环（2.4s，幅度小） | 唯一允许的动画，且只给正在干活的 |
| **需要你** | 右下角一个小圆点（accent 色） | 与"需要你"入口呼应 |
| 已暂停 | 去饱和 60% | 一眼看出它不接活 |
| 离线（本地节点） | 虚线环 | 不是它的错，是能力节点不在 |
| 失败/冲突 | 红色斜线角标 | 极少见，但要看得出 |

**不做**：不闪、不跳、不在列表里同时动多个（安静优先）。

## 8. 群聊图标

房间没有独立图片，用成员**小鸟头像**拼合（bot-avatar.md §5.5）：

```
≤3 人：2×2 / 横排小拼合
4 人：2×2
>4 人：2×2 + 右下 "+N"
```

拼合规则：按角色排序（host 第一），取前 4 个；host 的鸟戴王冠；成员信息拿不到时退化到 glyph。

## 9. 无障碍与一致性

- `alt` = Bot 名称（不写"头像"）
- 不只用颜色区分（glyph 族不同）
- 与文字对比度：glyph 描线对底色 ≥ 3:1
- 深浅色主题各渲染一次，不允许"只在深色下好看"

## 10. 数据模型

```sql
CREATE TABLE bot_icons (
  bot_id      TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL,
  kind        TEXT NOT NULL,        -- procedural | image
  shape       TEXT NOT NULL,        -- family id（procedural）
  palette     TEXT NOT NULL,
  seed        INTEGER NOT NULL,     -- 由 hash 派生，改色不改 seed
  image_id    TEXT,                 -- ContentStore 内容 id（kind=image）
  zoom        REAL NOT NULL DEFAULT 1,
  focus_x     REAL NOT NULL DEFAULT 0.5,
  focus_y     REAL NOT NULL DEFAULT 0.5,
  updated_at  INTEGER NOT NULL
);
```

## 11. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT | `/api/bots/:id/icon` | 上传（multipart） |
| POST | `/api/bots/:id/icon/generate` | 生成（需 provider key） |
| PUT | `/api/bots/:id/icon/crop` | 改 zoom / focus |
| PUT | `/api/bots/:id/icon/palette` | 改色 |
| DELETE | `/api/bots/:id/icon/image` | 退回程序化图标 |

## 12. 分期

### v0
- 程序化图标（SVG）+ 调色板；上传图片（256 WebP）
- **验收**：新 Bot 立刻有图标；同一 id 刷新后图标不变；深浅色都好看

### v1
- 裁剪（zoom/focus）、状态环、群聊拼合
- **验收**：改 zoom 后各处一致；工作中只动一个环

### v2
- AI 生成（provider 可选）、409 并发保护、原图重裁窗口
- **验收**：无 key 时生成入口不出现；生成失败不改变现有图标

## 13. 待决问题

1. **6 个族够不够**（768 组合，10 人团队够；大团队要更多族还是允许重复？）倾向：v1 加到 12 族。
2. **中文名要不要也进 hash**（改名后图标变不变？）倾向：只用 id，改名不变形象。
3. **群聊拼合上限**：固定 4 还是按屏幕宽度 3/4？倾向：固定 4，窄屏一样。
